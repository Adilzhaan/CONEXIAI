# Промт для Claude Code — Два слоя дашборда: Мониторинг (зоны) vs Оценка риска (типы)

> Вставь в Claude Code как задачу. Бэкенд — **FastAPI**, фронт — адаптируй под текущий. Связан с `prompt_client_formulas.md` (оценка по типам кризиса). Сначала прочитай существующий дашборд и модель сигналов.

---

## Проблема

На дашборде два набора карточек, и они **визуально выглядят одинаково** (большое число 0–100), из-за чего кажутся конкурирующими оценками:

- **Верх:** зоны мониторинга — `INFOFIELD & MEDIA 54`, `HUMAN RESOURCES 20`, `GOV. RELATIONS 39`, `PR ENVIRONMENT 51`, `MARKET & INDUSTRY 75`, `CI MONITOR 35`.
- **Низ:** оценка по типам кризиса (по формулам) — Финансовый, Операционный, Репутационный, Регуляторный, Поставщика.

Это разные вещи. Сейчас `Market 75` наверху пугает сильнее любого типа внизу, хотя это **не риск 75**, а уровень активности.

---

## Цель

1. **Верхний слой переоформить как «Мониторинг по зонам» (радар активности)** — увести от вида риск-скора. Это «что происходит и откуда».
2. **Нижний слой — «Оценка риска по типам»** остаётся слоем решений (формулы, тревоги). Не трогаем логику.
3. **Связать слои drill-down'ом:** клик по типу риска показывает, какие зоны/источники его «кормили».

```
ВЕРХ = РАДАР     → где активность, откуда сигналы (по функциям/отделам)   — наблюдение
НИЗ  = ДИАГНОЗ   → насколько опасно, по типам риска (по формулам)          — решения
Связь: сигналы из зон → факторы → баллы по типам (drill-down показывает провенанс)
```

---

## Верхний слой — «Мониторинг по зонам»

### Переименование и подача

- Заголовок секции: **«Мониторинг по зонам»** (или «Радар активности»). Подпись: «где сейчас активность · источники сигналов».
- **Число — это НЕ риск-скор, а уровень активности/внимания.** Подать иначе, чтобы не соперничало с формульными баллами внизу:
  - убрать формат «54 / 100» в стиле риска;
  - показать как **уровень активности** — полоса заполнения + подпись `Активность: высокая/средняя/низкая`, или бейдж, или число помельче с пометкой «активность», не «риск»;
  - тренд (↑/↓) оставить — он полезен («↑14 по Market» = зашевелилось).
- Зоны: Infofield & Media, Human Resources, Gov. Relations, PR Environment, Market & Industry, CI Monitor. Это **функции/отделы**, не типы риска.

### Что считает «активность зоны»

Активность зоны = объём + динамика сигналов в зоне (НЕ формула риска):

```python
zone_activity = normalize(signal_volume_24h, velocity, recency)  # 0–100, но это активность
```

Это справочный показатель «сколько шумит», а не оценка опасности. Опасность — только внизу, по типам.

## Связь слоёв (data model)

Чтобы drill-down работал, у каждого сигнала фиксируем: **из какой зоны** пришёл и **в какие типы риска** он вложился.

```python
signals(
  ..., zone str,                      # infofield_media | hr | gr | pr | market | ci
)

signal_contributions(                 # провенанс: сигнал → вклад в тип
  id, signal_id, crisis_type,         # financial | operational | reputational | regulatory | supplier
  factors jsonb,                      # извлечённые ИИ факторы 0–10
  contribution_score numeric          # вклад этого сигнала в балл типа
)
```

- При обработке сигнала: классифицируем зону + ИИ извлекает факторы → пишем вклад по типам.
- Балл типа (низ) агрегируется из `signal_contributions`. Drill-down по типу → берём его сигналы → группируем по `zone`.

Связь зон↔типов **не жёсткая 1:1** — она строится из реальных данных, а не хардкод-маппинга. (Можно дать мягкий дефолт-маппинг только для пустого состояния.)

---

## Drill-down (главное — связывает слои)

Клик по карточке типа внизу (напр. «Репутационный 34») открывает разбор:

```
Репутационный риск: 34 (средний)
  Формула: Охват 8 × Тональность 6 × Влияние аудитории 7 / 10 = 34

  Какие зоны это кормят:
    • Infofield & Media   — 5 сигналов  (вклад 60%)
    • PR Environment      — 2 сигнала   (вклад 40%)

  Топ-сигналы:
    • «вирусный негатив в Instagram» (Media, 50k охват)
    • «руководство признало проблемы на рынке» (PR)
```

И обратно (опц.): клик по зоне наверху → в какие типы риска уходят её сигналы.

## Эндпоинты

```
GET /dashboard/zones              — верх: зоны + активность + тренд + последний сигнал
GET /dashboard/types              — низ: типы + балл (из prompt_client_formulas) + уровень
GET /risk/types/{type}/breakdown  — drill-down: формула, факторы, зоны-источники, топ-сигналы
GET /dashboard/zones/{zone}/types — (опц.) обратный drill: в какие типы уходит зона
```

## Acceptance Criteria

1. Верхний слой переименован в «Мониторинг по зонам»; число подаётся как **активность**, не как риск-скор (нет формата «N/100» в стиле риска, есть пометка «активность»).
2. Нижний слой (типы) визуально и текстово обозначен как **оценка риска по формулам** — слой решений.
3. У сигнала есть `zone`; есть `signal_contributions` (сигнал → тип + факторы + вклад).
4. Балл типа агрегируется из вкладов сигналов; drill-down по типу показывает зоны-источники с долей вклада + топ-сигналы (тест: сумма вкладов зон ≈ балл/состав типа).
5. Связь зон↔типов берётся из данных, не из хардкод-маппинга.
6. Клик по типу открывает breakdown с формулой, факторами, зонами и сигналами.
7. Alembic-миграции чистые; есть тест на агрегацию вкладов.

## Чего НЕ делать

- НЕ показывать активность зоны как «риск N/100» — это вводит в заблуждение.
- НЕ принимать решения/тревоги по верхнему слою — тревоги только по типам (низ).
- НЕ хардкодить жёсткий маппинг зона→тип — строить из `signal_contributions`.
- НЕ дублировать логику оценки — баллы типов берём из движка `prompt_client_formulas`.

## Порядок реализации

1. Добавить `zone` сигналам + `signal_contributions` + миграции.
2. При обработке сигнала: классификация зоны + запись вкладов по типам.
3. Агрегация балла типа из вкладов (стыкуется с движком формул).
4. Эндпоинты zones / types / breakdown.
5. Фронт: переоформить верх как «Мониторинг по зонам» (активность, не риск).
6. Drill-down: карточка типа → зоны-источники + топ-сигналы.
